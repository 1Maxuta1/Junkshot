# JUNKSHOT

Многопользовательская игра на Roblox: зимняя свалка, сбор хлама, броски.
Код синхронизируется через Rojo, карта генерируется скриптом на Lune.

| Папка проекта | Где в Roblox |
|---|---|
| `src/shared` | `ReplicatedStorage.Shared` |
| `src/server` | `ServerScriptService.Server` (обычная Folder) |
| `src/client` | `StarterPlayer.StarterPlayerScripts.Client` |
| `src/map/Map.rbxm` | `Workspace.Map` (генерируется, см. ниже) |
| `tools/map/` | генератор карты (не попадает в игру) |

## Установка

1. `aftman install` — ставит `rojo` и `lune` (версии в `aftman.toml`).
2. ProfileStore лежит в `src/server/Packages/ProfileStore.luau`. Без него сервер остановится с ошибкой
   `ProfileStore ModuleScript not found`.
3. `rojo serve` → в Studio плагин Rojo → Connect.
   **Только один `rojo serve`.** Расширение Rojo для VS Code запускает его само. Если запустить второй
   вручную, Studio получает каждый новый файл дважды (так задвоились модули и `Workspace.Map`).
4. Карта: файл `src/map/Map.rbxm` уже собран. После правок генератора: `lune run tools/map/build`
   (из корня проекта), Rojo подхватит новый файл сам.

> Карту правят в `tools/map/build.luau` (раскладка) и `tools/map/Prefabs.luau` (детали).
> Изменения, сделанные в Studio прямо в `Workspace.Map`, Rojo перезапишет.

# Stage 2 — Recycling Machine

## Исправление: дубль предмета при броске

**Причина.** Клиент рисовал полёт своей копией предмета, а сервер после полёта создавал настоящий.
Копия убиралась, только если настоящий предмет приходил *после* её приземления. Обычно он приходил
раньше, и 1.5 с на земле лежали два одинаковых объекта (измерено в Studio).

**Исправление (один объект на uid всегда).** В момент броска сервер сразу создаёт *настоящий* предмет в
точке приземления, заблокированный на время полёта: подсказки нет, `Claim` отказывает. Перед тем как
объект уйдёт клиентам, сервер шлёт `ThrowFx`, а клиенты двигают по дуге **этот же** объект и ставят его
точно в серверную точку. Клиентских копий больше нет. Если места для приземления нет, предмет
возвращается в руки.

Цикл жизни предмета: мир → в руках → (бросок: тот же объект, заблокирован) → мир → машина → награда.

## Машина переработки

- **Модель** (`Prefabs.RecyclingMachine`, ~40 деталей) в центре площади. Оранжевый корпус, синее
  основание, жёлтый вход с дверцей, круглое окно камеры, экран с прогрессом, шестерни, поршень, три лампы,
  выходной лоток, знак «♻ RECYCLE» на крыше и снег на деталях. Модель `Persistent` для стриминга.
- **Взаимодействие.** Подсказка машины на своей клавише (**R** на ПК, **Y** на геймпаде, тап по карточке)
  и всегда видна, поэтому хлам рядом её не перекрывает. Она открывает панель: список того, что в руках,
  выбор предмета, кнопка RECYCLE.
- **Состояния** (только сервер): `Idle → AcceptingItem (1 с) → Processing (4.5 с) → RewardReady (4 с) → Idle`.
  Состояние публикуется атрибутами модели (`State`, `OwnerUserId`, `PhaseStartedAt` и др.), клиенты
  анимируют по ним. Опроса и отдельного remote для состояния нет.
- **Награда.** Редкость и предмет выбираются на сервере в момент вставки (`RewardService`, шансы в
  `Config/Rarities.luau`: 55 / 25 / 12 / 6 / 1.8 / 0.2 %). Предмет выдаётся через существующий
  `InventoryService.AddItem`, который присваивает ему уникальный uid. Новых систем предметов нет.
  `ItemConfig` пополнен 18 предметами-наградами (по 3 на редкость, у каждого своя модель из деталей).
- **Безопасность.** Один цикл за раз. Предмет изымается из рук без yield после проверок. Таймеры
  несут номер цикла. Награда выдаётся не больше одного раза. Клиент не задаёт ни длительность, ни
  редкость. Вставка только своего, носимого предмета и только рядом с машиной.
- **Выход владельца в любой момент.** `DataService.OnBeforeRelease` записывает награду в профиль до
  сохранения. Смерть ничего не меняет, награда идёт в инвентарь.
- **Если инвентарь полон** (1000 предметов), награда остаётся в лотке за владельцем (кнопка CLAIM), а при
  его выходе записывается в профиль.
- **Показ редкости.** Карточка награды усиливается по уровню: Common простая; Uncommon с цветным фоном;
  Rare со свечением и вспышкой частиц; Epic с вращающимся превью; Legendary с паузой-интригой, вращающимся
  бликом и светом; Mythic с радужным оформлением. В мире все видят лампы и окно в цвете редкости, предмет
  на постаменте и объявление «Игрок got Редкость Предмет!». Частицы только разовой вспышкой (`Emit`),
  свет только на время показа.
- **UI** (`UI/MachinePanel`, `UI/RewardReveal`): пока машина работает, панель сжимается в полоску с
  прогрессом, чтобы анимацию было видно. Всё в Scale с минимальными размерами, кнопки ≥ 44 px, на
  геймпаде фокус на первой карточке и B закрывает.

# Stage 1 — Core Gameplay

## Что сделано

**Карта «зимняя свалка»** (`tools/map`, ~1130 частей, ~1440 инстансов в Workspace)
- Центральная площадь с 4 точками спавна и зарезервированным местом под машину переработки
  (`Plaza.RecyclerSite`, тег `RecyclerSite`, жёлтая разметка).
- 4 дороги-«спицы» от площади к кольцевой дороге, кольцевая дорога соединяет всё.
- 4 зоны сбора по диагоналям, каждая со своим видом: **Container Stacks**, **Tire Mountain**,
  **Pine Hollow**, **Old Sheds**. В каждой зоне невидимая область с тегом `JunkSpawn`; реквизит стоит
  только по внешнему краю, внутренняя сторона к площади всегда открыта.
- 8 пустых участков под будущие базы (`BasePlots.Plot1..8`, тег `BasePlot`, атрибуты `PlotId`, `Owner`).
- Ориентиры в углах (кран, гора хлама, сосновая роща, мастерская), стена из контейнеров и
  невидимая стена-граница, сосны за стеной.
- Освещение: ShadowMap, мягкие голубые тени (Ambient/OutdoorAmbient), Atmosphere, лёгкая цветокоррекция и Bloom
  для неоновых ламп. 12 PointLight без теней, остальные лампы только неон.
- `StreamingEnabled = true`.

**Подбор** — существующая система Шага 3, доработана:
- Каждый объект хлама получил **uid**, который не меняется: на земле → в руках → в полёте → снова на земле.
  Один uid может быть только в одном месте (мир или список одного игрока); сервер это проверяет.
- Подсказка подбора нарисована в стиле игры (`UI/PickupPrompt`): клавиша E, кнопка X на геймпаде,
  тап на карточку на телефоне. Если руки полные, карточка красная: «Carry full».
- Брошенный или выпавший хлам исчезает через `Junk.DroppedLifetime` (300 с), если его никто не подобрал.
- Лимит хлама в мире `Junk.MaxActive = 150`. Удалённые модели возвращаются в пул и переиспользуются.

**Переноска**: до 6 предметов на спине (сетка 2×3, все приведены к одному размеру), приварены к
HumanoidRootPart без собственной физики. Состояние на сервере, клиент только рисует.

**Бросок** (`ThrowService` + `ThrowController`)
- Клиент отправляет только `(uid, точка прицела)`. Сервер сам берёт позицию персонажа, считает скорость
  при фиксированном угле (`Throw.LaunchAngle`) и ограничивает дальность `[MinRange, MaxRange]`.
- Дуга считается рейкастами (`Ballistics.Simulate`). Физических объектов в полёте нет: ничего нельзя
  толкнуть, раскрутить или задвоить. Попадание в стену — предмет падает перед ней.
- После полёта предмет появляется на земле с тем же uid; его может подобрать любой игрок.
- Ближайшие клиенты получают `ThrowFx` и рисуют полёт сами (одно Heartbeat-соединение на все полёты,
  только пока что-то летит; модели из пула).
- Сигнал `ThrowService.Landed(thrower, record, position, hitInstance)` — точка подключения для машины переработки.

**UI** (всё в Scale, с ограничениями размера)
- Хотбар на 6 слотов с 3D-превью хлама, выделение выбранного, название выбранного предмета.
- Счётчик `n/6`, красный и с пульсацией, когда полно.
- Кнопка броска на телефоне (только при сенсорном вводе), над уровнем кнопки прыжка.
- Тосты: «Picked up …», «Threw …», «Carry full (6/6)», «Nothing to throw».

# Данные и сохранение (Шаги 1–2, без изменений)

- `DataService` — ProfileStore: загрузка, сессионная блокировка, сохранение. При сбое загрузки игрока кикает.
- `CurrencyService` — единственный, кто меняет Klunks. `InventoryService` — единственный, кто меняет предметы (uid).
- `ReplicationService` — снимок и инкрементальные обновления только владельцу.
- `RemoteGuard` — лимиты запросов и проверка аргументов для всех remote от клиента.

Проверка сохранения: опубликованный опыт + Game Settings → Security → **Enable Studio Access to API Services**,
`UseMockStore = false`. В командной строке сервера:
```lua
local p = game.Players:GetPlayers()[1]
local C = require(game.ServerScriptService.Server.Services.CurrencyService)
print(C.AddKlunks(p, 250))
```
Остановить Play, снова Play → в Output клиента `[DataController] ready: 250 K`.
