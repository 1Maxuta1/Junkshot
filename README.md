# JUNKSHOT

Многопользовательская игра на Roblox: зимняя свалка, сбор хлама, броски.
Код синхронизируется через Rojo, карта генерируется скриптом на Lune.

| Папка проекта | Где в Roblox |
|---|---|
| `src/shared` | `ReplicatedStorage.Shared` |
| `src/server` | `ServerScriptService.Server` (обычная Folder) |
| `src/client` | `StarterPlayer.StarterPlayerScripts.Client` |
| `src/map/Map.rbxm` | `Workspace.Map` (генерируется, см. ниже) |
| `tools/map/` | генератор карты (не попадает в игру) |

## Установка

1. `aftman install` — ставит `rojo` и `lune` (версии в `aftman.toml`).
2. ProfileStore лежит в `src/server/Packages/ProfileStore.luau`. Без него сервер остановится с ошибкой
   `ProfileStore ModuleScript not found`.
3. `rojo serve` → в Studio плагин Rojo → Connect.
   **Только один `rojo serve`.** Расширение Rojo для VS Code запускает его само. Если запустить второй
   вручную, Studio получает каждый новый файл дважды (так задвоились модули и `Workspace.Map`).
4. Карта: файл `src/map/Map.rbxm` уже собран. После правок генератора: `lune run tools/map/build`
   (из корня проекта), Rojo подхватит новый файл сам.

> **Автотесты (DevTests)** по умолчанию выключены: они около минуты телепортируют персонажа.
> Чтобы их запустить, в Studio выделите ServerScriptService → Properties → Attributes → добавьте
> `RunDevTests` (boolean) = true и нажмите Play. Результат — в Output (`[DevTests] done: N passed`).

> Карту правят в `tools/map/build.luau` (раскладка) и `tools/map/Prefabs.luau` (детали).
> Изменения, сделанные в Studio прямо в `Workspace.Map`, Rojo перезапишет.

# Stage 4 — Bases, Chest, Buildings, Scrap Deliveries, Balance & Music

## Что изменилось для игрока

- **Хлам больше не появляется сразу после подбора.** Раз в 5 минут приходит «завоз»: свалка
  дозаполняется до цели, а в HUD идёт отсчёт «New scrap in 3:12». Обобранные места остаются пустыми,
  поэтому выгодно ходить по разным зонам.
- **Своя база на участке:**
  - сундук (C / L2 / тап);
  - 4 слота для построек (C), часть открывается расширением базы;
  - флаг с полосами по уровню базы;
  - машина, как и раньше.
- **Сундук = хранилище базы.** Положить или взять можно только у своего сундука. Уровни 1–5:
  10 / 20 / 35 / 55 / 80 предметов, модель меняется (ящик → сундук с оковкой → металлический
  контейнер → промышленный → защищённый блок).
- **Постройки на слотах:**
  - Scrap Conveyor — брошенный на ленту хлам уезжает в сундук;
  - Storage Rack — +15 слотов сундука;
  - Trophy Stand — показывает самый редкий предмет из сундука;
  - Warm Lantern — свет.

  Постройки можно улучшать (у конвейера 2 уровня скорости) и сносить с возвратом 50 %.
- **Музыка и звуки:** 5 зимних треков с плавной сменой; короткие сигналы на легендарку, мифик,
  крафт, редкую награду, улучшение и завоз хлама; кнопка SOUND: громкость музыки и эффектов, MUTE.
  Настройки сохраняются.

## Архитектура

| Модуль | Роль |
|---|---|
| `PlotService` (было) | какой участок у игрока в этой сессии (один на игрока, освобождается при выходе) |
| `BaseService` **новый** | база из сохранения `profile.Data.Base`: сундук, слоты, постройки, флаг; единый remote `BaseAction` |
| `Bases/BaseModels` **новый** | модели-заглушки (5 сундуков, площадки, постройки, флаг) |
| `Bases/Conveyor` **новый** | один цикл на все конвейеры |
| `StorageService` (было) | перенос руки ↔ сундук, теперь только у своего сундука (`BaseService.IsNearChest`) |
| `InventoryService` (было) | содержимое сундука (`profile.Items`, формат не менялся); лимит = `BaseService.GetStorageCapacity` |
| `JunkService` (было) | завозы, ячейки с перезарядкой, «природные» предметы, `MoveTo` / `ForEachClaimable` |
| `AudioService` **новый** | настройки звука и сигналы |
| Клиент `BaseController`, `AudioController` **новые** | окно слота; музыка, сигналы, окно SOUND |
| `Dev/BalanceSim` **новый** | теоретическая симуляция баланса (в игре не запускается) |

**Владение и безопасность.**
- В `BaseAction(requestId, action, slotId?, buildingId?)` нет id базы или участка: сервер всегда берёт
  базу вызывающего. Подделать чужую базу нечем.
- Каждое действие проверяется: данные загружены, request id новый (защита от дублей), игрок стоит на
  своей базе, слот существует и открыт, лимиты, уровень игрока, деньги.
- Строить можно только на заданных слотах. Если на слоте стоит размещённый предмет, стройка
  запрещена. Размещать предметы на слоты тоже нельзя (`PlacementRules`).

**Состояние.** База собирается из сохранения на любом участке и на любом сервере. Модели не
сохраняются, сохраняется только `Base = { Level, ChestLevel, Buildings }`.

## Завозы хлама (`GameConfig.Junk.Replenish`)

| Параметр | Значение | Смысл |
|---|---|---|
| `Interval` | 300 с | раз в 5 минут |
| `BaseTarget` / `PerPlayer` / `MaxTarget` | 50 / +8 / 130 | цель: 50 при одном игроке, 106 при восьми |
| `MaxActive` | 150 | жёсткий предел всех предметов в мире (включая брошенные) |
| `MinPlayerDistance` | 30 studs | новые предметы не появляются рядом с игроком |
| `CellSize` / `CellCooldown` | 24 studs / 240 с | свалка поделена на ячейки; ячейка с новым предметом ждёт |
| `BatchPerStep` | 4 | предметов за кадр во время завоза |
| `NaturalLifetime` | 1500 с | нетронутый предмет исчезает через 25 минут, но не на глазах у игрока |

Завоз не сбрасывает карту: он только дозаполняет недостающее. Для этого используются зоны JunkSpawn,
без сканирования всей карты; один таймер на всю свалку. Вероятности появления (`DropTables.WorldSpawn`)
отделены от вероятностей переработки и крафта.

## Баланс (оценка, а не измерения)

Симуляция `src/server/Dev/BalanceSim.luau` берёт реальные конфиги, Монте-Карло 300 сессий на
профиль. Запуск в Studio (Play, сервер): `print(require(game.ServerScriptService.Server.Dev.BalanceSim).Report())`.

**Изменено после симуляции:**
- **Таблица переработки** 55/25/12/6/1.8/0.2 → **70/22/6/1.6/0.35/0.05**. Раньше одна переработка
  стоила ~50 K против ~10 K за обычный предмет, а легендарки шли каждые 15–40 минут. Теперь ~25 K
  (в 2.5 раза выгоднее продажи хлама), легендарки и мифики стали редкими.
- **Дешёвые первые покупки подняты** (их брали через 2–3 минуты): Snow Boots 2 — 500 (было 250),
  Grabber Arm 2 — 600 (было 300), Bigger Backpack 2 — 800 (было 400), сундук 2 — 450, сундук 3 — 1000,
  расширение базы 2 — 1500.

| Профиль (оценка) | K/мин | Первое улучшение | Улучшение ≥ 1200 | Rare | Epic | Legendary | Mythic |
|---|---|---|---|---|---|---|---|
| Casual, 15 мин | ~70 | ~7 мин | не за сессию | 1/5 мин | 1/22 мин | 1/102 мин | 1/900 мин |
| Regular, 30 мин | ~90 | ~6 мин | ~28 мин (редко) | 1/4 мин | 1/17 мин | 1/80 мин | 1/450 мин |
| Active, 60 мин | ~116 | ~5 мин | ~47 мин | 1/3 мин | 1/12 мин | 1/58 мин | 1/346 мин |
| Efficient, 60 мин | ~143 | ~4 мин | ~39 мин | 1/2 мин | 1/9 мин | 1/46 мин | 1/305 мин |
| Collector, 60 мин | ~49 продажи | ~9.5 мин | не за сессию | 1/4 мин | 1/15 мин | 1/78 мин | 1/429 мин |
| 8 игроков, 30 мин | ~92 | ~5 мин | — | 1/4 мин | 1/15 мин | 1/73 мин | 1/529 мин |

Цели ТЗ:
- первое интересное открытие за 1–3 минуты — да (Rare каждые 2–5 минут);
- первое улучшение за 5–10 минут — да;
- значимое улучшение за 15–25 минут — **медленнее** (~30–45 минут). Частично это следствие того,
  что модель скупает все дешёвые покупки подряд; копящий игрок дойдёт быстрее. Это нужно проверить
  живым плейтестом;
- редкий предмет — дело нескольких сессий — да (мифик раз в 5–15 часов).

**Проверенные эксплойты:**
- бесконечная переработка закрыта (Stage 3: перерабатывается только хлам свалки);
- крафт → продажа не дороже ингредиентов (тест);
- магазин дороже продажи (тест);
- продажа + вывод из хранилища не дублирует предметы (один uid);
- AFK: опыт и деньги только за действия, завозы ограничены целью.

**Открытый риск (без вашего одобрения не менял):** клики ускорения по 10 в секунду ускоряют
шестичасовой мифический крафт примерно до 36 минут непрерывного автоклика. Предлагаю ограничить
долю ускорения кликами (например, ≤ 50 % задания). Механику «1 клик = 1 секунда» не трогал.

# Stage 3 — Economy & Player Progression

Валюта одна — **Klunks** (`GameConfig.Klunks`: имя, символ, лимит; переименовать, например, в
«Scrap Coins» можно одной строкой). Сохранённое поле в профиле по-прежнему `Klunks`.

## Что получил игрок

- **Баланс, уровень и опыт** в правом верхнем углу; при заработке и трате всплывает «+120 K / −500 K».
- **Scrap Dealer** — лавка в центре площади (R / Y / тап по карточке). Три вкладки:
  - **SELL** — всё из рук и хранилища с ценами. Можно выбрать предметы и нажать SELL, или нажать
    SELL ALL (второе нажатие подтверждает продажу).
  - **SHOP** — материалы, детали и полезные предметы; часть открывается с уровнем.
  - **UPGRADES** — улучшения игрока.
- **Сумка** (B / View / кнопка BAG):
  - «В руках» и «Хранилище базы», фильтры ALL / MATERIALS / USABLE / VEHICLES / COLLECTIBLES;
  - кнопки STORE и TAKE работают только на своём участке.
- **Уровни 1–50.** Опыт дают:
  - открытие нового вида предмета — один раз на каждый вид;
  - готовая переработка или крафт, мифический крафт;
  - продажа: 1 XP за каждые 10 K.

  Уровень открывает товары магазина и улучшения.
- **Стартовый баланс** — 25 K (только для новых профилей).

## Архитектура

| Модуль | Роль |
|---|---|
| `CurrencyService` (было) | единственный, кто пишет `data.Klunks` |
| `EconomyService` **новый** | единый путь для всех движений денег: Earn/Spend с причиной и id, журнал (50), защита от дублей по request id (60, сохраняются в профиле), событие `EconomyFx` клиенту |
| `SellService` **новый** | продажа (проверки ниже) |
| `ShopService` **новый** | покупки из `Config/ShopConfig` |
| `PlayerUpgradeService` **новый** | улучшения игрока из `Config/PlayerUpgrades` и их эффекты |
| `ProgressionService` **новый** | уровень и опыт из `Config/Progression` |
| `StorageService` **новый** | перенос руки ↔ хранилище (тот же uid) |
| `DealerService` **новый** | лавка на площади (модель-заглушка) и `IsNear` |
| `InventoryService` (было) | хранилище базы: `profile.Items[uid]`, лимит по улучшению, перенос с сохранением uid |
| `MachineService` (было) | улучшения машины теперь списываются через `EconomyService` |
| Клиент `EconomyController/` | `Hud`, `Dealer`, `Bag`, общий `Window` |

Клиент никогда не присылает суммы, цены, уровни или результат. Он присылает только id предметов,
id товара или улучшения и случайный request id. Повтор запроса с тем же request id ничего не делает.

## Состояния предмета (один uid — ровно одно место)

| Состояние | Где | Как попадает | Продаётся? |
|---|---|---|---|
| В руках | `CarryService` (`profile.Carry`) | подбор, лоток машины, магазин, TAKE | да |
| В хранилище | `InventoryService` (`profile.Items`) | STORE на базе, магазин при полных руках | да |
| Размещён / транспорт | `PlacementService` (`profile.Deployed`) | G → Place | нет (сначала T — Pick up) |
| В машине / на лотке | `MachineService` (`profile.Machine`) | переработка, крафт | нет |
| В тележке | `Behaviors/Cart` (`Deployed[i].Contents`) | Z — Load | нет (сначала выгрузить) |
| Лежит в мире | `JunkService` | бросок, выпадение | нет |

Все хранители uid подключены к `JunkService.RegisterUidSource`, а у `InventoryService` есть проверка
uid. Поэтому один uid физически не может оказаться в двух местах. Переносы идут без yield: сначала
удалить, потом добавить, а при неудаче вернуть на место.

## Продажа — проверки сервера

Продажа проходит, только если всё верно (иначе не продаётся ничего):
1. request id новый;
2. игрок у лавки (16 studs);
3. от 1 до 40 разных корректных uid;
4. каждый uid — в руках или хранилище этого игрока;
5. каждый предмет продаётся;
6. выплата не превышает лимит баланса.

После этого предметы удаляются и деньги начисляются один раз, в одном шаге без yield.

## Цены (`Config/EconomyConfig`, `Util/ItemValue`)

- **Природные предметы:** база по редкости (Common 10, Uncommon 30, Rare 90, Epic 220, Legendary 600,
  Mythic 1800) ±40 % (стабильный разброс по id).
- **Крафтовые:** 0.85 × стоимость ингредиентов. Функциональные — не ниже 0.6 × базы редкости, но
  **никогда** не дороже ингредиентов, поэтому крафт ради продажи невыгоден.
- **Особые цены:** `dented_trophy` 110, `toxic_barrel` 95, `crystal_shard` 260; `aurora_reactor` не
  продаётся.
- **Магазин:** цена продажи × 4, округлённая вверх до 5 (или явная цена). При загрузке проверяется, что
  каждая цена магазина выше цены продажи — купить и перепродать невыгодно.
- **Защита от бесконечных денег:** перерабатывать можно только хлам со свалки (`Category = "Junk"`).
  Награды, материалы и крафт обратно в переработку не идут. В мифический крафт по-прежнему идёт что
  угодно (3 → 1, 6 часов).

Примеры цен: Rusty Can 12, Old Tire 12, Copper Wire 34, Circuit Board 116, Dented Trophy 110,
Snow Globe 7, Arcade Joystick 95, Aurora Orb 768, Dragon Egg 2467; Bicycle 26, Homemade Car 132,
Metal Detector 160. Магазин: Metal Sheet 40, Bolt Pack 50, Copper Wire 140 (ур. 2), Circuit Board 465
(ур. 5), Bicycle 1200 (ур. 3), Metal Detector 2500 (ур. 4).

## Улучшения игрока (`Config/PlayerUpgrades`)

| Улучшение | Уровни (эффект / цена / ур. игрока) |
|---|---|
| Bigger Backpack (руки) | 6 → 7 (400, ур. 2) → 8 (1500, ур. 4) → 9 (5000, ур. 7) |
| Snow Boots (скорость) | 16 → 17 (250) → 18 (800, ур. 3) → 19 (2000, ур. 5) → 20 (5000, ур. 8) |
| Grabber Arm (дальность подбора) | 10 → 12 (300, ур. 2) → 14 (1200, ур. 4) → 16 (3500, ур. 6) |
| Base Storage (хранилище) | 30 → 60 (300) → 100 (1000, ур. 3) → 160 (3000, ур. 5) → 250 (8000, ур. 8) |
| Haggler (бонус продажи) | 0 → +3 % (1000, ур. 3) → +6 % (4000, ур. 6) → +10 % (12000, ур. 10) |

Улучшения машины (скорость, лоток, уровень) остались в машине. Шесть часов мифического крафта и
1 клик = 1 секунда не изменены.

## Как добавить товар, улучшение, цену

- **Товар:** одна строка в `ShopConfig.Entries`.
- **Своя цена предмета:** `EconomyConfig.ItemOverrides[id] = { SellPrice = … }` или `{ CanBeSold = false }`.
- **Улучшение:** запись в `PlayerUpgrades` плюс эффект в `PlayerUpgradeService` (для новых типов).
- **Опыт:** числа в `Config/Progression`.

## Сохранение

`ProfileVersion` = 4. Миграция 3 → 4 ничего не меняет, а `Reconcile` добавляет `PlayerUpgrades`,
`Progress { Level, XP, Discovered }` и `Economy { Transactions, Requests }`. `Klunks` и `Items`
сохраняют прежний формат.

ProfileStore даёт сессионную блокировку, автосохранение, сохранение при выходе и остановке сервера,
а также повторы при ошибках. При неудачной загрузке игрок кикается, и данные не перезаписываются

## Как пользоваться

1. Выбрать предмет в хотбаре (1–6, LB/RB, тап). Над хотбаром появляется кнопка действия.
2. **G** / D-pad ↑ / тап по кнопке:
   - **Place** — полупрозрачный предпросмотр перед игроком: зелёный — можно, красный — нельзя
     (причина видна). Подтвердить: G, ЛКМ, R2 или PLACE. Отмена: Q, B или CANCEL.

3. Размещённые объекты управляются подсказками (у каждого действия своя клавиша):

| Объект | E / X (геймпад) | Z / D-pad ← | X / D-pad → | T / D-pad ↓ |

| Велосипед, машина | Ride / Drive (только владелец) | — | — | Pick up (владелец) |
| Машина, пассажирское место | Ride along (любой) | — | — | — |
| Тележка | Tow / Release | Load | Unload | Pick up (только пустую) |
| Радио | Play / Stop (любой) | Next song (любой) | — | Pick up (владелец) |

Вождение: WASD / стрелки / левый стик / экранный стик. Выход: Space / A / прыжок / кнопка EXIT.

## Архитектура

| Часть | Файл |
|---|---|

**Состояния предмета** (один uid всегда ровно в одном): *в руках* (CarryService) ↔ *размещён*
(PlacementService, сохраняется в `profile.Data.Deployed`) / *лежит в мире* (JunkService) / *в тележке*.
Переходы проверяются и выполняются без yield, повторный запрос не проходит. Размещённые uid и
содержимое тележек сообщаются в `JunkService.RegisterUidSource`, поэтому CarryService не примет такой
uid второй раз.

**Правила размещения:** не дальше 18 studs от игрока, только на земле карты, ровная поверхность, не
на чужом участке, не ближе 10 studs к машине, без пересечений. Лимит — 5 объектов на игрока, из них
2 транспорта.

**Транспорт — авторитетно на сервере.** Физика машины всегда принадлежит серверу, даже с седоком.
Клиент только передаёт газ и руль в [−1, 1] (remote `VehicleInput`, лимит частоты), принимается это
только от текущего водителя. Скорость, торможение, задний ход и поворот считает сервер
(LinearVelocity в плоскости + AlignOrientation). Машина едет на невидимых шарах-коллайдерах, поэтому
переезжает бордюры. Чужого за рулём высаживает. После высадки владение персонажем возвращается
игроку. Упавшая с карты машина возвращается на место установки.

**Выход и смерть:** смерть, высадка и уход игрока освобождают место. Если уходит владелец, его
объекты убираются из мира (записи остаются), пассажиров аккуратно высаживает. При следующем входе
объекты ставятся на участок владельца; если места нет, предмет возвращается в руки.

**Звуки** (бесплатные, работают в любой игре): двигатель — «Car-Engine-Loop» (Roblox Resources), радио —
три трека APM Music, писк металлоискателя — встроенный `electronicpingshort.wav`.

## Архитектура машины

- **Один `MachineService`** на сервере, машины хранятся по игрокам. Remotes (`MachineRecycle`,
  `MachineCraft`, `MachineMythic`, `MachineAccelerate`, `MachineTake`, `MachineUpgrade`) **не принимают id

- **Состояния:** `Idle → Processing → RewardReady → Idle`. Задание хранит `StartedAt` и `Duration` во
  времени `Workspace:GetServerTimeNow()`. Результат выбирается в момент запуска. На задание ставится один
  `task.delay` с токеном, циклов опроса нет.
- **Сохранение:** `profile.Data.Machine` = `{ Job?, Output, Upgrades, BoostUntil, InstantCredits, ResultSeq }`,
  руки — в `profile.Data.Carry`, обработанные чеки — в `profile.Data.Purchases`. `ProfileVersion` = 2,
  новые ключи добавляет Reconcile.
- **Синхронизация с клиентом** только атрибутами модели машины (`State`, `JobKind`, `JobLabel`,

  `LastResultId/Rarity` …). Клиент раз в секунду обновляет таймер локально.
- **Лоток:** предметы спавнятся через `JunkService.SpawnAt` с `ReservedFor = владелец` и колбэком
  `OnClaimed`, который синхронно (без yield) убирает предмет из `Output`. Поэтому предмет не может быть
  одновременно и на лотке, и в руках. Чужой подбор — ошибка `Reserved`. На клиенте чужие подсказки
  скрыты.
- **Длительность:** `база × множитель Speed × геймпасс × активный буст`, не меньше `MinDuration` (5 с).
  Мифический крафт — всегда ровно 6 ч (ускоряют только клики и Instant Finish).

# Stage 2 — Recycling Machine (история, заменено Stage 2A)

## Исправление: дубль предмета при броске

**Причина.** Клиент рисовал полёт своей копией предмета, а сервер после полёта создавал настоящий.
Копия убиралась, только если настоящий предмет приходил *после* её приземления. Обычно он приходил
раньше, и 1.5 с на земле лежали два одинаковых объекта (измерено в Studio).

**Исправление (один объект на uid всегда).** В момент броска сервер сразу создаёт *настоящий* предмет в
точке приземления, заблокированный на время полёта: подсказки нет, `Claim` отказывает. Перед тем как
объект уйдёт клиентам, сервер шлёт `ThrowFx`, а клиенты двигают по дуге **этот же** объект и ставят его
точно в серверную точку. Клиентских копий больше нет. Если места для приземления нет, предмет
возвращается в руки.

Цикл жизни предмета: мир → в руках → (бросок: тот же объект, заблокирован) → мир → машина → награда.

## Машина переработки

- **Модель** (`Prefabs.RecyclingMachine`, ~40 деталей) в центре площади. Оранжевый корпус, синее
  основание, жёлтый вход с дверцей, круглое окно камеры, экран с прогрессом, шестерни, поршень, три лампы,
  выходной лоток, знак «♻ RECYCLE» на крыше и снег на деталях. Модель `Persistent` для стриминга.
- **Взаимодействие.** Подсказка машины на своей клавише (**R** на ПК, **Y** на геймпаде, тап по карточке)
  и всегда видна, поэтому хлам рядом её не перекрывает. Она открывает панель: список того, что в руках,
  выбор предмета, кнопка RECYCLE.
- **Состояния** (только сервер): `Idle → AcceptingItem (1 с) → Processing (4.5 с) → RewardReady (4 с) → Idle`.
  Состояние публикуется атрибутами модели (`State`, `OwnerUserId`, `PhaseStartedAt` и др.), клиенты
  анимируют по ним. Опроса и отдельного remote для состояния нет.
- **Награда.** Редкость и предмет выбираются на сервере в момент вставки (`RewardService`, шансы в
  `Config/Rarities.luau`: 55 / 25 / 12 / 6 / 1.8 / 0.2 %). Предмет выдаётся через существующий
  `InventoryService.AddItem`, который присваивает ему уникальный uid. Новых систем предметов нет.
  `ItemConfig` пополнен 18 предметами-наградами (по 3 на редкость, у каждого своя модель из деталей).
- **Безопасность.** Один цикл за раз. Предмет изымается из рук без yield после проверок. Таймеры
  несут номер цикла. Награда выдаётся не больше одного раза. Клиент не задаёт ни длительность, ни
  редкость. Вставка только своего, носимого предмета и только рядом с машиной.
- **Выход владельца в любой момент.** `DataService.OnBeforeRelease` записывает награду в профиль до
  сохранения. Смерть ничего не меняет, награда идёт в инвентарь.
- **Если инвентарь полон** (1000 предметов), награда остаётся в лотке за владельцем (кнопка CLAIM), а при
  его выходе записывается в профиль.
- **Показ редкости.** Карточка награды усиливается по уровню: Common простая; Uncommon с цветным фоном;
  Rare со свечением и вспышкой частиц; Epic с вращающимся превью; Legendary с паузой-интригой, вращающимся
  бликом и светом; Mythic с радужным оформлением. В мире все видят лампы и окно в цвете редкости, предмет
  на постаменте и объявление «Игрок got Редкость Предмет!». Частицы только разовой вспышкой (`Emit`),
  свет только на время показа.
- **UI** (`UI/MachinePanel`, `UI/RewardReveal`): пока машина работает, панель сжимается в полоску с
  прогрессом, чтобы анимацию было видно. Всё в Scale с минимальными размерами, кнопки ≥ 44 px, на
  геймпаде фокус на первой карточке и B закрывает.

# Stage 1 — Core Gameplay

## Что сделано

**Карта «зимняя свалка»** (`tools/map`, ~1130 частей, ~1440 инстансов в Workspace)
- Центральная площадь с 4 точками спавна и зарезервированным местом под машину переработки
  (`Plaza.RecyclerSite`, тег `RecyclerSite`, жёлтая разметка).
- 4 дороги-«спицы» от площади к кольцевой дороге, кольцевая дорога соединяет всё.
- 4 зоны сбора по диагоналям, каждая со своим видом: **Container Stacks**, **Tire Mountain**,
  **Pine Hollow**, **Old Sheds**. В каждой зоне невидимая область с тегом `JunkSpawn`; реквизит стоит
  только по внешнему краю, внутренняя сторона к площади всегда открыта.
- 8 пустых участков под будущие базы (`BasePlots.Plot1..8`, тег `BasePlot`, атрибуты `PlotId`, `Owner`).
- Ориентиры в углах (кран, гора хлама, сосновая роща, мастерская), стена из контейнеров и
  невидимая стена-граница, сосны за стеной.
- Освещение: ShadowMap, мягкие голубые тени (Ambient/OutdoorAmbient), Atmosphere, лёгкая цветокоррекция и Bloom
  для неоновых ламп. 12 PointLight без теней, остальные лампы только неон.
- `StreamingEnabled = true`.

**Подбор** — существующая система Шага 3, доработана:
- Каждый объект хлама получил **uid**, который не меняется: на земле → в руках → в полёте → снова на земле.
  Один uid может быть только в одном месте (мир или список одного игрока); сервер это проверяет.
- Подсказка подбора нарисована в стиле игры (`UI/PickupPrompt`): клавиша E, кнопка X на геймпаде,
  тап на карточку на телефоне. Если руки полные, карточка красная: «Carry full».
- Брошенный или выпавший хлам исчезает через `Junk.DroppedLifetime` (300 с), если его никто не подобрал.
- Лимит хлама в мире `Junk.MaxActive = 150`. Удалённые модели возвращаются в пул и переиспользуются.

**Переноска**: до 6 предметов на спине (сетка 2×3, все приведены к одному размеру), приварены к
HumanoidRootPart без собственной физики. Состояние на сервере, клиент только рисует.

**Бросок** (`ThrowService` + `ThrowController`)
- Клиент отправляет только `(uid, точка прицела)`. Сервер сам берёт позицию персонажа, считает скорость
  при фиксированном угле (`Throw.LaunchAngle`) и ограничивает дальность `[MinRange, MaxRange]`.
- Дуга считается рейкастами (`Ballistics.Simulate`). Физических объектов в полёте нет: ничего нельзя
  толкнуть, раскрутить или задвоить. Попадание в стену — предмет падает перед ней.
- После полёта предмет появляется на земле с тем же uid; его может подобрать любой игрок.
- Ближайшие клиенты получают `ThrowFx` и рисуют полёт сами (одно Heartbeat-соединение на все полёты,
  только пока что-то летит; модели из пула).
- Сигнал `ThrowService.Landed(thrower, record, position, hitInstance)` — точка подключения для машины переработки.

**UI** (всё в Scale, с ограничениями размера)
- Хотбар на 6 слотов с 3D-превью хлама, выделение выбранного, название выбранного предмета.
- Счётчик `n/6`, красный и с пульсацией, когда полно.
- Кнопка броска на телефоне (только при сенсорном вводе), над уровнем кнопки прыжка.
- Тосты: «Picked up …», «Threw …», «Carry full (6/6)», «Nothing to throw».
